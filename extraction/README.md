# SADKO Group — Site Extraction & Rebranding Graph

Full structural extraction of **https://www.sadko-group.com/**, prepared as a handoff package for page-by-page rebranding.

Extracted **2026-07-18**.

---

## The single most important finding

The site looks like it has **501+ pages**. It does not.

| Layer | Count | Editable? |
|---|---|---|
| WordPress pages (Divi) | 10 | ✅ Yes — page files |
| WordPress posts (Arabic slugs) | 4 | ✅ Yes — post editor |
| Divi Theme Builder templates (header + footer) | 2 | ✅ Yes — affects **every** page |
| Ecwid store templates (category + product) | 2 | ⚠️ Via Ecwid design settings + CSS only |
| Ecwid **virtual routes** (30 categories + 471 products) | 501 | ❌ Not pages. Generated by the 2 templates above. |

**The shop is Ecwid** (SaaS storefront, store ID `18028328`) injected as a JavaScript widget into a single WordPress page. Its 501 URLs are client-side routes driven by catalog data — there are no files to rebrand individually.

**So the real rebranding surface is 18 things, not 501.** Restyling the 2 Ecwid templates re-skins all 501 store routes at once; restyling the 2 Divi Theme Builder templates re-skins every page on the site.

**Stack:** WordPress · Divi theme · Ecwid (`ecwid-shopping-cart` plugin) · built by "The Wizards" · Arabic RTL primary, EGP.

## Top issues to fix during rebrand

**High severity**
- The hotline **"19140" is a raster image**, not text — not tap-to-call, not selectable, invisible to SEO and screen readers. It appears in the header on *every page*.
- **Policy pages are English-only** on an Arabic RTL site — legal and trust content unreadable to the primary audience.
- **No installment offering anywhere on the site.** SADKO was founded in 1986 on installment sales and states it on the About page, but there is no calculator, no plan, no mention in the store. Biggest commercial gap.

**Medium severity**
- Divi factory blue `#2ea3f2` still live, clashing with the `#7ebec5` brand teal
- `/track-your-order/` is a "Coming Soon" dead end sitting in the primary nav
- Parent category pages show only subcategory tiles — no copy, no hero, no SEO value
- Footer copyright hardcoded to **2024**
- Two visual systems collide: Divi chrome vs. Ecwid storefront defaults
- Store name inconsistent: `SADKO Group` vs. `Sadko Groups`

**Low severity**
- Only a white logo variant exists — no dark, mono, or print lockup
- `حرف يدوية ومنتجات عضوية` (Handicrafts & Organic) is an odd fit in an appliance catalog
- Showrooms lack working hours, maps, and photography

**Also missing sitewide:** product reviews, spec tables, related products, stock indicators, Arabic store UI strings, WhatsApp contact, Instagram/TikTok, newsletter capture, after-sales/warranty portal, privacy & cookie policy.

## Caveats

- Product **prices and descriptions** were not scraped per-SKU. Ecwid's public API is token-gated and product pages are JavaScript-rendered. `catalog.json` carries IDs, Arabic names, and URLs; the product **template schema** in `site-graph.json` documents every field a product page renders. This was the agreed scope — all 471 products share one template, so per-SKU scraping adds no rebranding value.
- Category → product membership is not mapped (it lives in Ecwid's backend). The parent/child **category tree** in `site-graph.json` is inferred from subcategory tiles and naming.
- To get full per-SKU data later, either request an Ecwid API token from the store owner (`/api/v3/18028328/products`) or export the catalog CSV from the Ecwid control panel — both far cleaner than scraping.
